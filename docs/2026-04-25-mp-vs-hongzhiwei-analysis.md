# MP 数据集上 E7/E8/E12 不如 E4 的诊断

## 1. 问题

在鸿之微 bandgap 数据集上：

- `E12` 明显优于 `E4`
- `E13` 进一步优于 `E12`

但在 Materials Project bandgap 数据集上：

- `E4` 重新成为最优模型
- `E7 / E8 / E12` 全部没有超过 `E4`

这说明问题不是“注意力超节点路线完全无效”，而是这条路线的收益具有明显的数据集依赖性。

## 2. 直接结论

先给最终判断：

1. `MP 更小，所以双槽位没有用` 这个解释不成立。
2. `E7 / E8 / E12` 在 MP 上失败，不是因为没有训练满，也不是因为 gate 完全塌缩。
3. 真正的问题是：`num_atoms` 在 MP 上不是一个可靠的“是否需要第二个全局槽位”的代理变量。
4. `E4` 的简单 virtual node 是更稳的归纳偏置，而 `E7 / E8 / E12` 在 MP 上引入了额外全局容量，但这些容量没有学出稳定、可泛化的分工。

## 3. 两个数据集上的核心结果

### 3.1 鸿之微

| 实验 | MAE | RMSE | R2 |
| --- | ---: | ---: | ---: |
| `E4` | 0.220077 | 0.474616 | 0.907663 |
| `E8` | 0.228456 | 0.494547 | 0.899745 |
| `E12` | 0.217873 | 0.471199 | 0.908988 |
| `E13` | **0.211944** | **0.461645** | **0.912641** |

鸿之微上结论很清楚：

- `E12 > E4`
- `E13 > E12`

### 3.2 MP

| 实验 | MAE | RMSE | R2 | Best Epoch |
| --- | ---: | ---: | ---: | ---: |
| `E2` | 0.239663 | - | - | - |
| `E4` | **0.230159** | **0.512199** | **0.885399** | 50 |
| `E7` | 0.239001 | 0.527332 | 0.878527 | 48 |
| `E8` | 0.241759 | 0.526103 | 0.879093 | 43 |
| `E12` | 0.236332 | 0.518681 | 0.882480 | 48 |

MP 上结论同样很清楚：

- `E4` 最好
- `E12` 比 `E7 / E8` 稍强，但还是输给 `E4`
- 所以 `size-supervised dual-slot` 不是完全无效，只是没有超过最稳的单超节点方案

## 4. “MP 更小”这个解释被数据否掉了

测试集结构规模统计：

| 数据集 | mean(num_atoms) | median | `>80` 占比 | `>160` 占比 |
| --- | ---: | ---: | ---: | ---: |
| 鸿之微 | 29.007 | 20 | 0.0505 | 0.0037 |
| MP | 31.333 | 20 | 0.0763 | 0.0116 |

这说明：

- MP 不是更小
- MP 反而有更高比例的大结构样本

所以不能再用“MP 结构太小，所以第二个槽位派不上用场”来解释。

## 5. 分桶结果说明：问题不是结构大不大，而是 size 监督用错了

### 5.1 鸿之微

鸿之微上，按 `num_atoms` 分桶后：

- `E4` 在 `<=80` 原子范围内最稳
- `E8` 在 `>80` 的大结构桶里开始优于 `E4`
- `E12 / E13` 进一步把这种“大结构受益”变成了整体收益

这意味着在鸿之微上，`结构规模` 与 `额外全局建模容量的收益` 确实存在相关性。

### 5.2 MP

MP 上，按 `num_atoms` 分桶后：

- `E4` 在几乎所有桶里都压过 `E7 / E8 / E12`
- 即便是在 `>80` 的大结构桶，`E4` 仍然没有被稳定超过

因此 MP 上的真实结论是：

- 大结构不自动意味着第二个槽位更有用
- `num_atoms -> 打开 slot2` 这条监督逻辑，在 MP 上不成立

## 6. 训练动态说明：不是没跑满，也不是没收敛

MP 上的 best epoch：

- `E4`: 50
- `E7`: 48
- `E8`: 43
- `E12`: 48

这说明：

1. 这些实验都基本跑满了 50 epoch 的有效训练区间。
2. 不是因为提早停下。
3. 不是因为还没来得及收敛。

更细一点看：

- `E7 / E8` 在 MP 上前期若干 epoch 有时能短暂优于 `E4`
- 但到后期，`E4` 会继续下降，而 `E7 / E8` 更早进入平台区

这说明额外全局机制不是完全学不到东西，而是：

- 前期能提供一些粗粒度全局帮助
- 但后期不能转化成更高的最终精度
- 反而拖累了最终的局部精细拟合

## 7. Gate 没有塌，但学到的不是有用分工

MP `E12` 的测试统计：

- `slot2_enable_mean = 0.121097`
- `global_fusion_strength_mean = 0.370807`

鸿之微 `E12`：

- `slot2_enable_mean = 0.027893`
- `global_fusion_strength_mean = 0.322875`

鸿之微 `E13`：

- `slot2_enable_mean = 0.106071`
- `global_fusion_strength_mean = 0.743466`

这三个数非常关键。

它说明：

1. MP 上 `slot2` 并没有完全塌到 0。
2. MP 上 `slot2` 的开启程度甚至高于鸿之微 `E12`。
3. 但“开得更多”并没有带来更好结果。

所以不能说“MP 失败是因为第二个槽位没打开”。

真正的问题是：

- 第二个槽位虽然打开了
- 但它没有学出真正有帮助的功能分工

## 8. E12 的机制本身决定了它会踩这个坑

`E12` 的配置与实现可以概括为：

- 前向结构是双槽位 gated virtual node
- `size` 不进入前向 gate 输入
- 但训练时会用 `num_atoms` 构造一个 sigmoid 目标去监督 `slot2_gate_logit`

这意味着 `E12` 的核心假设是：

> 原子数越大，第二个槽位越应该打开。

而 MP 的结果表明，这个假设在该数据集上不成立。

## 9. 更合理的根因解释

目前最可信的解释有三层。

### 9.1 第一层：代理变量失配

`num_atoms` 不是 MP 上 bandgap 难度和全局依赖强度的好代理。

原因很可能包括：

- bandgap 是强烈依赖局部化学环境和成键模式的性质
- MP 中单胞原子数的变化，不一定对应电子结构复杂度的单调增加
- 不同材料的 cell 选取方式会让 `num_atoms` 带有表征口径噪声

也就是说：

- 在鸿之微里，`大结构 -> 更需要第二槽位` 大致成立
- 在 MP 里，这个映射不稳定

### 9.2 第二层：额外全局容量没有学出清晰分工

`E7 / E8 / E12` 比 `E4` 多了额外的全局交互通道，但 MP 上没有形成可靠 specialization。

表现是：

- 前期有帮助
- 后期不如 `E4`
- 打开了 slot2，但收益没有出来

这通常意味着：

- 容量加了
- 但学习目标没有告诉模型“什么时候该用第二槽位、第二槽位要学什么”

### 9.3 第三层：E4 的归纳偏置本身更稳

`E4` 只做一件简单的事情：

- 用一个 virtual node 做全图汇聚

这个偏置很朴素，但在 MP 上很稳，因为：

- 不依赖额外路由
- 不依赖复杂 gate
- 不依赖错误的结构尺度先验

## 10. 这对后续改进意味着什么

如果目标是做一篇“私有数据集和公开数据集都能赢”的路线，那么下一步不应该继续硬押 `num_atoms`。

更合理的方向是：

1. 保留 `E4` 作为稳定主干。
2. 让第二槽位的开启依据来自“样本真实收益”，而不是来自 `num_atoms`。
3. 强制两个槽位学出不同职责，而不是都去抢同一类全局信息。

最值得做的方案是：

- 用 `E4` 和 `E8` 做 teacher
- 在验证集或训练集上标出每个样本“谁更准”
- 用这个 teacher preference 去监督 gate

这样做的优点：

- 不再假设 `大结构 == 该开第二槽位`
- gate 直接学习“什么时候双槽位真的更有收益”
- 这个监督信号比 `num_atoms` 更贴近最终目标

## 11. 一句话结论

MP 上 `E7 / E8 / E12` 输给 `E4`，不是因为模型没训够，也不是因为 MP 结构更小，而是因为 `num_atoms` 在 MP 上不是有效的 gate 监督信号，导致额外全局槽位没有学出稳定有益的分工；而 `E4` 的单超节点归纳偏置更简单、更稳，所以重新成为最优解。
