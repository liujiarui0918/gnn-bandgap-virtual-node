# 全局注意力与超节点方案统计分析

## 1. 统计目标

本文档针对测试集 `9551` 个结构，按结构大小 `num_atoms` 分桶，比较以下 5 个模型在 `band_gap` 任务上的表现：

- `E2`：ALIGNN baseline
- `E4`：超节点 only
- `E5`：全局注意力 only
- `E7`：1 个 attentive 超节点
- `E8`：2 个 attentive 超节点

核心问题是两类：

- 全局注意力和超节点，哪条路线更有效
- 不同结构规模下，模型改动和关键参数变化会带来什么影响

各实验的结构性差异如下：

| 实验 | 全局注意力 | 超节点数 | 关键差异 |
| --- | --- | --- | --- |
| E4 | 无 | 1 | 朴素 virtual node |
| E5 | 有 | 0 | 3 层 Transformer, 8 heads |
| E7 | 有 | 1 | 1 个 attentive virtual node |
| E8 | 有 | 2 | 2 个 attentive virtual node + slot 间 self-attention |

需要强调两点：

- `E7 -> E8` 基本可以视为把 attentive 超节点从 `1` 个改成 `2` 个，这是最接近纯参数影响的对比。
- `E5` 不是纯参数 ablation。它同时改了 `transformer_layers / attention_heads / lr / batch_size`，因此更适合作为一条模型路线来评估，不适合当作单一参数结论。

## 3. 统计方法

- 数据集：官方测试集，共 `9551` 个样本
- 主分桶字段：`num_atoms`
- 指标：测试集 `MAE`，越低越好
- 分桶方式：
  - `<=10`
  - `11-20`
  - `21-40`
  - `41-80`
  - `81-160`
  - `>160`

补充说明：

- `>160` 桶仅有 `35` 个样本，趋势有参考价值，但结论应谨慎解读。
- 本统计主要回答“不同结构规模下哪种全局信息建模方式更有效”，而不是严格做单变量参数消融。

## 5. 直接观察

### 5.1 E4 最稳

`E4` 在 `<=80` 原子的所有分桶中都是最优或近似最优方案，说明：

- 对小中型晶体结构，简单超节点已经足够有效
- 朴素全局汇聚比复杂全局注意力更稳健

### 5.2 E5 这条全局注意力路线整体不如超节点

`E5` 只在 `<=20` 原子时相对 `E2` 略有改善，但所有分桶都输给 `E4`：

- `<=10`：`E5 - E4 = +0.0109`
- `11-20`：`E5 - E4 = +0.0113`
- `21-40`：`E5 - E4 = +0.0235`
- `41-80`：`E5 - E4 = +0.0277`
- `81-160`：`E5 - E4 = +0.0132`
- `>160`：`E5 - E4 = +0.0211`

这说明“全图全局注意力 only”并没有成功替代超节点机制。

### 5.3 E7 明显失败

`E7` 在所有分桶都显著差于 `E4`，表明：

- attention 不是天然加分项
- 单个 attentive 超节点并没有解决全局信息瓶颈
- 反而引入了更复杂但不够有效的全局交互

### 5.4 E8 在大结构上开始反超

`E8` 在小中图里没有超过 `E4`，但在大结构上开始体现优势：

- `81-160`：`E8 0.3736 < E4 0.3796`
- `>160`：`E8 0.2696 < E4 0.2930`

这说明：

- 对大结构，单一超节点可能容量不足
- 当结构规模继续增大时，多槽位全局表示开始更有价值

## 6. 最关键的参数影响：超节点数 `1 -> 2`

`E7 -> E8` 是最接近纯参数影响的一组对比，即：

- `num_virtual_nodes: 1 -> 2`

对应各分桶的 `MAE` 变化如下：

| 原子数桶 | E7 | E8 | E8 - E7 |
| --- | ---: | ---: | ---: |
| `<=10` | 0.2226 | 0.1272 | `-0.0955` |
| `11-20` | 0.2912 | 0.2060 | `-0.0852` |
| `21-40` | 0.3552 | 0.2548 | `-0.1005` |
| `41-80` | 0.4419 | 0.3422 | `-0.0997` |
| `81-160` | 0.5190 | 0.3736 | `-0.1454` |
| `>160` | 0.3462 | 0.2696 | `-0.0767` |

结论很明确：

- 问题不在 attention 这个想法本身
- 问题在于 `1` 个全局槽位明显不够
- 把超节点数从 `1` 提到 `2` 后，收益非常稳定
- 这种收益在大结构上更明显

## 7. 路线层面的综合判断

可以把这 4 条路线概括为：

- `E4`：简单超节点
- `E5`：纯全局注意力
- `E7`：单 attentive 超节点
- `E8`：双 attentive 超节点

综合统计结果可得：

- 小中型结构：`简单超节点 > 全局注意力`
- 大型结构：`双超节点 + 轻量全局注意力` 开始体现优势
- 单个 attentive 超节点路线不可取

换句话说：

- `超节点` 是主线
- `全局注意力` 更适合作为增强模块，而不是直接替代超节点

## 8. 汇报可直接使用的结论

可以直接用下面这段话汇报：

> 我们按测试集 9551 个结构，基于 `num_atoms` 做了分桶统计。结果表明，朴素超节点方案 `E4` 在小中型结构上最稳，而纯全局注意力方案 `E5` 整体不如超节点。单个 attentive 超节点 `E7` 明显失败，说明问题不在 attention 本身，而在单一全局槽位容量不足。进一步把 attentive 超节点从 1 个增加到 2 个后，得到 `E8`，其在所有分桶相对 `E7` 都显著改善，并且在大结构上开始超过 `E4`。因此当前最合理的结论是：超节点是主线，全局注意力更适合作为大结构增强器，而不能硬替代超节点。 

## 9. 最终一句话总结

- `全局注意力 only`：不如超节点
- `1 个 attentive 超节点`：失败
- `2 个 attentive 超节点`：有效，且对大结构更友好
- 当前最合理方向：以超节点为主体，在大结构场景下引入轻量全局注意力增强
